# IEPL 专线、IPLC 与公网 BGP 中转：到底有什么区别？

## 四大常见线路架构全景对比

| 线路类型 | 跨境路径 | 晚高峰稳定性 | 典型成本 | 适合场景 |
| --- | --- | --- | --- | --- |
| **普通公网直连** | 本地宽带 → 民用国际出口 → 海外 VPS | 较差（晚高峰易丢包限速） | 极低 | 自建轻度学习或冷门时段访问 |
| **国内 BGP 公网中转** | 本地宽带 → 国内 BGP 中转 → 公网优质出口 → 海外落地 | 中等偏上（依赖出口路由质量） | 中低 | 日常浏览、性价比中轻度流媒体 |
| **IEPL 以太网内网专线** | 本地宽带 → 国内专线入口 → 以太网专线过境 → 海外落地 | 高（受超卖程度影响） | 中高 | AI 办公、4K 流媒体、远程开发主力 |
| **IPLC 点对点国际专线** | 本地宽带 → 运营商点对点专线 → 海外落地 | 高 | 高 | 对延迟抖动敏感的跨境团队、语音与高频业务 |

## 普通用户如何理性看待“专线”宣传？

1. **不要被“5 元全线顶级 IPLC 不限速”误导**：真正独享或低超卖的跨境专线每 Mbps 采购成本高昂，极低价套餐必然通过更高的共享复用比或流量限制来平衡成本。
2. **关注“不限速”背后的单线程晚高峰表现**：白天大家都在上班时，普通中转也能跑满千兆宽带；真正拉开差距的是晚上 21:00 看 4K 视频或拉取 GitHub 仓库时是否断流。
3. **主备搭配采用不同架构**：建议用一家运营年限长、开放第三方订阅的 IEPL 专线做主力（如 [光速云](/reviews/guangsuyun) 或 [星岛梦](/brands/xingdaomeng)），再配一份不限时一次性流量包作为应急冗余，详见 [晚高峰主备双活策略](/airport/stable/evening-peak-backup-strategy)。

## 深入拆解：为什么晚高峰公网丢包 3% 就会让百兆宽带瞬间卡成几百 KB？

许多新手疑惑：“我家办了 500M 宽带，就算晚高峰丢包 3%–5%，剩下 95% 的带宽不也有 475M 吗，为什么看个 1080P 视频一直转圈？”

根据经典的 **Mathis TCP 吞吐上限估算公式**（\`Max_Throughput ≈ (MSS / RTT) × (1 / sqrt(p))\`）：
- 当跨太平洋美国线路 `RTT = 160ms`、且公网拥堵导致丢包率 `p = 3%`（`0.03`）时，单条 TCP 连接的理论极限吞吐会被拥塞控制算法（CUBIC/Reno）直接压低到不足 **0.4 MB/s（约 3 Mbps）**；
- 而如果走 **IEPL / IPLC 内网专线**抵达香港节点（`RTT = 22ms`、`p ≈ 0%`），物理延时降低 7 倍且无公网拥堵丢包，单条 TCP 即可轻松跑满本地宽带上限。

### 五项实操鉴别与选型硬标准
1. **看重三网入口质量**：无论电信 163、联通 4837 还是移动 CMI，国内端必须有就近 BGP 多线入口，避免南方用户在北方中转绕行多增加 30ms 延迟。
2. **核对单线程而非 32 线程跑分**：只有单线程或少线程在晚 20:30–22:30 保持平稳曲线，才说明专线采购带宽真正充足。
3. **验证客户端生态开放度**：优质专线配合 [Clash Verge Rev 规则引擎](/clash/verge/) 可实现国内直连 + 海外专线 + AI 分区，比闭源专属端发挥更大价值。
4. **核实代表品牌数据档案**：可对照查阅 [光速云评测](/reviews/guangsuyun)、[暮光加速评测](/reviews/muguang)、[唯兔云评测](/reviews/weitu) 与 [星岛梦评测](/reviews/xingdaomeng) 中的真实报价与实测差异。
5. **警惕多倍率与虚标专线文案**：不少中低价位机场仅在核心 2–3 个高倍率节点（如 `2x`/`3x`）采购少量 IEPL，其余常规 `1x` 节点仍是公网 BGP 中转。购入前务必核对流量结算倍率规则（参考 [流量倍率常见疑问](/resources/faq/billing-multiplier-faq)）。

## 四、技术架构深水区：隧道协议搭配（AnyTLS / VLESS-Reality / Shadowsocks）

专线解决的是**跨境物理路径不拥堵**的问题，而协议栈解决的是**入口连接不被干扰与握手效率**的问题。在实际工程部署中，不同线路架构搭配不同协议往往会产生截然不同的用户体验：

| 线路类型 | 常见搭载协议 | 技术原因与工程取舍 |
| :--- | :--- | :--- |
| **IEPL / IPLC 内网专线** | Shadowsocks-2022 / Trojan / AnyTLS / VLESS | 因为数据过境走企业内网专线，入口通常只需要常规 BGP 转发加密载荷；使用轻量级协议反而能大幅降低 CPU 加解密开销，在单线程下榨干千兆带宽（如光速云珠海联通 9Gbps 批次基于 VLESS 单线程跑出 300–420 MB/s） |
| **公网 BGP 中转** | Trojan / VLESS-Reality / Hysteria 2 | 中转机与海外落地之间经过公网出口时可能遇到突发 QoS 或连接重置，采用 TLS 伪装与多路复用抗压协议更能保证长连接不频繁断流 |
| **纯公网直连** | VLESS-Reality + uTLS / Hysteria 2 | 直连缺乏国内入口中转保护，必须依赖 Reality 偷取高可信域名握手指纹或 Hysteria 2 暴力发包来对抗 3%–5% 的公网晚高峰丢包 |

### 实操自测：如何在 1 分钟内判断手头专线是否被晚高峰“超卖”？

即使机场货真价实租用了 IEPL 专线，如果商家将一条 1Gbps 物理专线卖出 500 份并发套餐（高超卖比），到了晚上 21:00 依然会阻塞。用户可通过三个简单观测指标自助诊断：

1. **连续 ICMP / TCP Ping 抖动幅度**：白天延时 `24ms ± 1ms`，若晚高峰跃升至 `65ms` 且出现明显尖刺（如突然跳到 `140ms`），证明国内中转机或过境隧道已经产生队列拥塞。
2. **YouTube 4K 测试「统计信息（Stats for nerds）」**：右击视频开启详细统计信息，观察 `Connection Speed` 稳定值。真正宽裕的专线即使在 21:30 也能轻松维持 `60,000–120,000 Kbps`，且 `Buffer Health` 迅速拉满至 30 秒以上。
3. **同一品牌不同入口横向对比**：如发现上海入口晚上 21 点卡顿，可立刻切换同一城市的深圳/广州移动或联通 BGP 入口（如支持多线入口切换），往往能避开单个省级运营商带宽打满的瓶颈。

### 常见线路选型误区与常见问题（FAQ）

#### 1. 对普通用户而言，IEPL 和 IPLC 实际体验差别大吗？
两者都属于不经过普通公网国际出口的内网跨境专线，晚高峰抗拥堵和低延迟能力都明显优于纯公网直连。IEPL 是以太网封装、带宽调度更弹性；IPLC 是点对点物理/SDH 级电路。对终端用户而言，运营商入口质量与服务商是否超卖，往往比标签写 IEPL 还是 IPLC 影响更大。

#### 2. 仅凭一张测速截图能证明一家机场真的是 IEPL/IPLC 专线吗？
不能。测速图只能证明当前时段的延迟和吞吐，无法直接验证底层物理合同。需要结合晚高峰连续丢包率、入口 ASN 归属、延迟抖动和长期社区口碑综合判断。

1. **误区 A：“海外落地机配置越高，我就越不卡”** — 实际上决定 95% 晚高峰体验的瓶颈不在海外落地 VPS 的 CPU 核数，而在于**中国大陆出口到海外服务器之间的跨境传输段**。公网直连遇到国际出口丢包时，哪怕落地用双路旗舰服务器也同样转圈。
2. **误区 B：“买了 IPLC/IEPL 专线就一定能在所有机场上解锁全 AI 和流媒体”** — 专线只负责把你的数据包稳定、高速、低丢包地送达海外入口，而 ChatGPT / Gemini / Netflix 是否放行，则完全取决于最末端**落地出口 IP 的 ASN 归属与纯净度（IPRisk）**，两者属于不同网络层概念。
3. **误区 C：“只要名字写着 IEPL，5 元一个月和 35 元一个月品质一样”** — 物理内网跨境带宽成本是透明刚性的，极低价套餐若号称全线 IEPL，通常会在单用户并发、晚高峰节点限速、流量倍率（`2x–5x`）或超高复用超卖上找补，务必优先以单线程晚高峰实测为准。
